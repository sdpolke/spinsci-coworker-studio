## Overview

Exotel is an India-first cloud telephony platform. SpinSci's Exotel integration streams call audio over Exotel's **AgentStream** WebSocket protocol — 16-bit linear PCM, mono, 8 kHz.

The two directions use different Exotel features:

- **Outbound** uses the [Connect Voice AI API](https://docs.exotel.com/exotel-agentstream/connect-voice-ai-api). SpinSci hands Exotel the media WebSocket URL on the dial request itself, so no App Bazaar flow is involved.
- **Inbound** uses a **Voicebot applet** in an App Bazaar flow. Exotel fetches a URL you configure on the applet, and SpinSci answers with the per-call WebSocket URL.

<Note>
  Both the Voicebot applet and the Connect Voice AI API may need to be enabled
  on your account. If you don't see the Voicebot applet in App Bazaar, or the
  `StreamType` parameter is rejected, contact Exotel support or your account
  manager.
</Note>

## Prerequisites

- An [Exotel account](https://exotel.com/) with AgentStream / Voicebot enabled
- **API Key** and **API Token** from **API Settings → API Credentials**
- Your **Account SID** (e.g. `mycompany1a`)
- At least one **ExoPhone** (virtual number)
- SpinSci AI instance publicly reachable over HTTPS and WSS

## Configuration

### Step 1: Get Exotel Credentials

1. Log in to the [Exotel Dashboard](https://my.exotel.com/)
2. Go to **API Settings** → **API Credentials**
3. Copy the **API Key**, **API Token**, and **Account SID**
4. Note which data centre your account lives in — Mumbai (`api.in.exotel.com`) or Singapore (`api.exotel.com`)

### Step 2: Configure in SpinSci AI

1. Navigate to **/telephony-configurations** and click **Add configuration**
2. Select **Exotel** as your provider
3. Enter your credentials:
   - API Key
   - API Token
   - Account SID
   - Data Centre — pick the host matching your account
   - Inbound Callback Token — *optional*. Leave blank and SpinSci generates one on save.
4. Click **Save Configuration**
5. Open the new configuration and add at least one **phone number** — your ExoPhone, in [E.164](https://en.wikipedia.org/wiki/E.164) format (`+` then country code then number, no spaces or dashes, e.g. `+918043071383`)

<Note>
  Exotel's dial API inverts the usual parameter naming: the number Exotel dials
  is sent as `From`, and the ExoPhone shown to the callee is `CallerId`. SpinSci
  handles this for you — the phone numbers you add to the configuration are
  used as the caller ID.
</Note>

### Step 3: Test Your Configuration

1. Open a workflow and click **Call** to place a test call
2. Check the run's call logs for a successful stream start

## Inbound Calling Setup

Exotel routes inbound calls through App Bazaar flows, and there is no public API to set an applet's URL. **This step is manual** — SpinSci shows you the exact URL to paste when you assign an inbound workflow.

### Step 1: Assign an Inbound Workflow to the ExoPhone

1. Go to **/telephony-configurations** and open your Exotel configuration
2. In the **Phone numbers** section, edit the ExoPhone that should receive calls
3. Set its **Inbound workflow** to the agent that should answer, and save
4. SpinSci shows a notice containing your Voicebot applet URL — copy it. It looks like:

```
https://api.SpinSci.com/api/v1/telephony/exotel/voicebot?account_sid=<ACCOUNT_SID>&token=<INBOUND_TOKEN>
```

You can also rebuild it yourself from the **Account SID** and **Inbound Callback Token** shown on the configuration. On self-hosted SpinSci, replace `api.SpinSci.com` with your backend domain.

### Step 2: Build the App Bazaar Flow

1. In the Exotel Dashboard go to **App Bazaar** and create a new **Custom App**
2. Add a **Voicebot** applet
3. Set the applet **URL** to the URL from Step 1 — as an `https://` URL, not `wss://`. Exotel fetches it per call and SpinSci replies with the `wss://` endpoint for that specific call.
4. Leave **Custom parameters** empty — the `account_sid` and `token` values are already on the URL
5. Save the app

### Step 3: Bind the ExoPhone to the Flow

1. Go to **ExoPhones** in the Exotel Dashboard
2. Edit the ExoPhone you assigned the inbound workflow to
3. Point it at the Custom App you created in Step 2
4. Save

### Test Inbound Calling

1. Call your ExoPhone from another phone
2. Verify your SpinSci voice agent answers
3. Check call logs in both the SpinSci dashboard and the Exotel Dashboard

## Security

Exotel does not sign App Bazaar callbacks, so SpinSci authenticates them with the **Inbound Callback Token** carried on the applet URL. The same token is appended to the outbound status-callback URL. Two consequences:

- Treat the Voicebot applet URL as a secret. Anyone holding it can start inbound runs against your organization.
- Additionally whitelist Exotel's outbound IP ranges at your edge or load balancer where you can. Ask Exotel support for the current ranges.

If you clear the Inbound Callback Token, inbound requests are accepted without verification and SpinSci logs a warning on every call.

## Limitations

- **Call transfer is not supported.** The AgentStream leg exposes no conference or bridge primitive, so there is no way to hand the caller to a human without dropping them. Transfer tools won't be offered on Exotel runs.
- **Per-call cost is not reported.** Exotel bills in the account currency (INR for Mumbai) with no exchange rate on the call-details response, so SpinSci records duration but leaves cost at zero.
- **Phone-number ownership isn't pre-validated.** Exotel's ExoPhone inventory API is still `v2_beta`, so SpinSci accepts the numbers you enter and lets a wrong caller ID fail at dial time instead.
- **Inbound routing is console-side.** SpinSci cannot push the Voicebot applet URL for you; assigning an inbound workflow surfaces the URL as a notice rather than syncing it.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Outbound call is rejected with an API error">
    - Confirm the **Data Centre** matches your account — a Mumbai account will
      not authenticate against `api.exotel.com`
    - Verify the API Key and Token are current and haven't been rotated
    - Confirm the caller ID on the configuration is an ExoPhone your account
      owns
    - Confirm AgentStream / Connect Voice AI is enabled on your account
  </Accordion>

  <Accordion title="Call connects but there is no audio">
    - Exotel streams linear PCM, not mu-law. If you proxy the WebSocket, make
      sure nothing rewrites frames.
    - Confirm your edge allows WebSocket upgrades on the `wss://` endpoint
    - Check the run logs for an Exotel `start` event; if it never arrives, the
      applet or dial request never reached SpinSci's socket
  </Accordion>

  <Accordion title="Inbound calls aren't answered">
    - Verify the Voicebot applet URL is the `https://` SpinSci URL, including
      both `account_sid` and `token` parameters
    - Confirm the ExoPhone is bound to the App Bazaar flow containing that
      applet
    - Confirm the same number exists in your SpinSci Exotel configuration and
      has an **Inbound workflow** assigned
    - Check that the number in SpinSci is stored in E.164 form — Exotel sends
      local formats like `08043071383`, which SpinSci normalizes to
      `+918043071383`
  </Accordion>

  <Accordion title="Inbound requests are rejected as unauthorized">
    The `token` parameter on the applet URL no longer matches the **Inbound
    Callback Token** on the configuration. Copy the current token from
    /telephony-configurations and update the applet URL in App Bazaar.
  </Accordion>

  <Accordion title="Call outcomes aren't recorded">
    Outbound status callbacks go to
    `/api/v1/telephony/exotel/status/<run_id>`. Confirm your backend is
    reachable over HTTPS from Exotel and that no proxy strips the `token`
    query parameter.
  </Accordion>
</AccordionGroup>

## Best Practices

- Use a dedicated App Bazaar flow for SpinSci so the Voicebot applet URL isn't shared with other systems
- Test with a single call before running campaigns
- Rotate the Inbound Callback Token by editing the configuration, then update the applet URL in App Bazaar
